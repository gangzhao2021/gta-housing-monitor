# 项目规格：Toronto Housing Leading Indicator

版本：0.7 · 建立／复核日期：2026-09-23 · 状态：设计基线；本地实现与验收状态见 HANDOFF 和 PROJECT_ACCEPTANCE

本文件将用户需求和已接受的技术路线落成可实施约定。信号阈值、数据系列选择及数据可用性尚未验证，不代表用户逐条批准了模型参数。

阅读约定：“已接受”指用户确认的方向；“初版约定”是后续实现默认遵循的设计；“候选／待验证”不可作为已经生效或有效的模型。执行进度和来源验证结果集中记录在 HANDOFF 与后续来源覆盖表，本文件保留长期规则。

## 1. 目标与读者

让不熟悉数据分析的使用者，每个月理解 GTA 转售市场的购买条件、成交需求和库存压力是否改善，并观察这些变化是否随后反映到价格。

主要观察窗口为未来 3–6 个月；人口与建设供应另设 1–3 年背景区。这些是产品观察窗口，不是已证实的指标领先期。

每月回答：

1. 融资和就业条件在支持还是拖累买家？
2. 买家是否实际回场，改善是否持续并覆盖多个市场？
3. 库存压力是否缓解，可能由成交增加还是挂牌减少推动？
4. HPI 是否确认价格趋稳？
5. Condo 是否存在交付、未售库存与租赁压力？

分别展示“变化方向”和“当前强弱”。改善中的弱市不能标成全面复苏；成交回升不能等同房价上涨。

## 3. 地区与房型约定

- 后续扩展以[实施计划](IMPLEMENTATION_ROADMAP.md)为细化合约：口径与缺失说明、数据补齐、关键图表与地区地图、自动更新、部署验收依次推进；部分界面和图表已落地，未改变既有MVP门槛。各阶段验收以计划状态表和[验收状态](PROJECT_ACCEPTANCE.md)为准。
- 租赁的物业类型、卧室数量与出租范围分别编码。当前月度公寓／condo合并均值不能称为整个租赁市场，也不能拆成单独condo；house、townhouse、整套／主层／地下室等新增范围须核验来源后接入。地下室不是与独立屋互斥的建筑类型。
- 转售总量先保留 TRREB 官方报告的原始市场范围，不擅自改称严格行政 GTA。
- 宏观就业和人口优先 Toronto CMA，清楚标示为背景代理；不冒充 City of Toronto 或 GTA。
- GTA、Toronto CMA、GTHA、City of Toronto 分别编码，不能自动合并。
- 分子和分母必须同一地区、房型、期间与统计口径。
- 房型优先总住宅、detached、condo apartment；地域拆分在字段和历史覆盖验证后确定。半独立屋、镇屋可后续扩展。
- 不允许将总市场季调系数未经验证直接用于细分市场。
- 地区边界或分类变更需记录断点，不能静默拼接成连续序列。

## 4. 指标字典草案

以下为项目指标与指标族定义，部分已有具体来源并接入，其他仍是候选。实际入库系列 ID、来源版本和范围见本规格来源表及数据字典。一个实际 series 必须只有一个定义和单位；`employment`、`hpi`、`rental_market` 等是分组，入库时拆成独立指标。例如 HPI 指数与 benchmark price 分开，就业人数、就业率与参与率分开。来源原单位及倍率另存，不能把“千人”直接当“人”。

| 指标／指标族 | 定义／选择要求 | 原始频率与单位 | 作用与限制 |
| --- | --- | --- | --- |
| boc_policy_rate | BoC 隔夜目标利率；与 Bank Rate 区分 | 按生效日，% | 融资背景，不单独判定利好 |
| goc_5y_yield | 加拿大政府 5 年基准国债收益率 | 交易日，% | 固定按揭融资环境，不等于按揭报价 |
| mortgage_rate | 主系列优先验证新增放款的固定细分类；固定／浮动、实际期限档、保险状态分别记录，存量另列 | 月，% | 全国报告机构的金额加权均值；新增放款包含续贷和再融资；存量利率用于还款压力背景 |
| resale_sales | 报告期间已报告的转售成交数量，不擅自解释为交割数量 | 月，套 | 需求活动，记录原始和官方季调版 |
| new_listings | 当月新增挂牌记录 | 月，条／套，按原定义 | 不等于独立业主或去重房屋数 |
| active_listings | 月末有效挂牌存量 | 月末，条／套，按原定义 | 存量，不能将多个月相加 |
| moi_raw | 同口径月末有效挂牌 ÷ 当月成交 | 月，库存月数 | 本项目自算原始口径；与其他机构公式区分 |
| snlr_raw | 同口径当月成交 ÷ 新挂牌 × 100 | 月，% | 不代表本月新挂牌的售出概率 |
| hpi | MLS HPI；指数与 benchmark price 分开存储 | 月，指数或 CAD | 价格确认；不与均价混为一谈 |
| unemployment_rate | Toronto CMA 失业率，固定季调与平滑口径 | 月，% | 结合就业与参与情况判断 |
| employment | 同地区就业人数、就业率、劳动参与率分别建系列 | 月，人数／% | 避免将退出劳动力市场误判为就业改善 |
| population | 同边界 CMA 人口估计、同比变化 | 年，人数／% | 长期背景，不插值生成月度事实 |
| housing_starts | 开始建设的住宅单位，按用途和房型分开 | 月，套；SAAR 另列 | 实际套数与季调年率不可混算 |
| under_construction | 在建单位存量 | 按官方频率，套 | 供应管线，不是当期新增流量 |
| completions | 竣工单位流量，区分 condo 与出租用途 | 月，套 | 近期交付压力，不能全部视为上市出售 |
| unabsorbed_inventory | 按来源定义的建成未吸纳库存 | 按官方频率，套 | 与转售有效挂牌、新盘可售库存区分 |
| condo_new_sales | 开发商新房成交；纯预售若可分辨则另建系列 | 月／季，套 | 核实在建、已建成、取消交易及地理覆盖 |
| rental_market | 同来源同范围租金、空置率等分别存储；当前 CMHC Toronto CMA RMS 已分别接入专建出租与出租公寓产权房空置率、两卧平均租金 | CMHC 每年 10 月调查，年度，CAD／% | 挂牌租金、新租约租金、存量平均租金不可混用；两类调查不可合并 |

备选确认指标：上市至成交时间、成交价／挂牌价；实施前核对重挂牌是否重置天数以及挂牌价的定义。

### 完整性补充：进入扩展路线，不扩大 MVP

| 内容 | 要补上的问题 | 实施边界 |
| --- | --- | --- |
| 购买力／月供情景（优先） | 利率下降后，同样贷款的月供减轻多少？房价变化是否抵消改善？ | 先固定贷款本金、摊还年限、产品、付款及复利约定，只改变利率；房价＋首付变化作为另一情景。显示全部假设，不能称为典型家庭的真实负担 |
| 收入与住房负担（后续） | 房价、月供相对家庭收入是否更容易承受？ | 有可比地区与时期的家庭收入才计算；平均工资不等于家庭收入，年度收入不伪造月度增长。来源不足时保留情景计算 |
| 贷款条件与政策事件（优先） | 利率相同，但贷款资格或购房成本是否变化？ | 记录贷款资格、税费、移民及重要住房政策；区分公告日、生效日、地区、适用对象、状态和原始来源，不把公告直接当利好或自动加分 |
| 家庭还款压力（可选） | 转售弱势是否同时伴随还款压力？ | 逾期率等作为风险背景，保留机构覆盖与省级／全国范围，不能冒充 Toronto 的领先信号 |
| Condo 持有成本（后续） | 租金能否覆盖持有成本，是否存在出售压力？ | 在租赁数据基础上明确管理费、税、保险、维修／空置和融资假设；租金不能直接当净收益，情景不冒充真实投资者现金流 |

利率、就业、成交和库存仍为核心。上述扩展必须有明确解释用途及独立信息价值；与现有指标重复或没有可靠来源的内容留在待办，不为“齐全”进入评分。

标准化月供只是融资成本的另一种表达，不与利率重复加权，也不是银行报价或获批额度。计算需验证计息换算，不能默认所有年利率都可直接除以 12。Condo 情景的本息还款用于现金流，不能全部当作经营费用计算净收益率。

政策事件是可编辑记录，不是时序数值。初版可手工维护，修正留痕；回测时只使用判断日已公告的资料。贷款规则参数不写死成永远有效的常数，也不只凭当期规则重算全部历史。

### 计算与展示

- Sales、挂牌等数量显示水平、同比和可用的季调趋势。
- 利率和失业率变化用百分点或基点，避免含混的“下降百分之几”。1 个百分点＝100 个基点。
- 债券收益率保留日度，月度主视图用当月有效交易日均值，月末最后有效观测作为辅助值。
- 政策利率月度显示月末有效目标，同时保留生效日。尚未结束的月份明确标成月内数据。
- 月度按揭利率使用官方月值，不将其伪装成当天报价。
- 按揭字典记录报告机构覆盖和金额加权方法。均值变化可能受机构权重和贷款组合影响，不能直接解释为同一买家的报价变化；来源的“5 years and over”必须标为“五年及以上”，不能改称纯五年产品。[BoC 表及 Notes](https://www.bankofcanada.ca/rates/banking-and-financial-statistics/interest-rates-for-new-and-existing-lending-by-chartered-banks/)
- MOI 与 SNLR 分母为零时返回缺失值及原因，不输出无穷大或填零；SNLR 大于 100% 不自动视为错误。
- 原始库存不能直接除以季调成交并标成标准 MOI。季调库存压力方案需单独定义和验证。
- 初版无可靠季调的序列用同比和历史同月比较，不用原始环比直接触发转向信号。
- 官方已为三个月移动平均的序列不默认再平滑。不同平滑口径不能拼接。
- 数量／指数同比＝本期值 ÷ 上年同月值 − 1；同比百分比显示时乘 100。零分母或缺少可比期时留空并解释。利率差值使用本期减比较期，保留百分点单位。
- “当前强弱”需要独立、版本化的比较基准；在基准尚未确定前只展示水平、同比和可用历史位置，不自动贴“强市／弱市”标签，不把全国经验阈值直接套到 GTA。
- 目标展示窗口为最近 24–36 个完整月份；实际采集需再覆盖计算的前置期。例如展示 36 个月同比需要至少 48 个月原始月值。覆盖不足时缩短相应计算区间，不缩写成“无变化”。

## 6. 数据架构

路线：原始来源 → 导入与校验 → SQLite 观测与版本 → 派生指标 → Streamlit。

建议逻辑结构如下，不要求第一阶段全部建表。MVP 建系列、观测和导入记录；派生指标可用查询／视图实现。信号阶段再实现信号快照，缓存和表数量按实际需要决定。

- `series`：系列 ID、指标、来源系列 ID、原始／标准单位与倍率、频率、地区及边界版本、房型、用途、季调状态、平滑状态、定义和来源链接。
- `observations`：系列 ID、期间起止、值、该版本发布日期（未知则留空）、该版本可用时间及证据、首次见到时间、抓取时间、版本、原始文件引用、质量状态。
- `ingestion_runs`：来源、执行时间、成功／失败、错误摘要、行数和内容哈希。
- `derived_observations`：派生值、公式版本、输入观测版本引用、计算时间。
- `signal_snapshots`：评估月份、判断时点、规则版本、快照修订版本、各项输入观测版本及期间、各维度结果、覆盖情况及可读解释。

发布日、首次见到时间、抓取时间、所属期间是不同概念，不可互相替代。

每次修订有自己的可用时间，不能沿用原始值的发布日期。历史某版本的发布时间有可靠证据时采用该时间；没有证据时，首次抓取仅证明“此时已见到此版本”，不能推断它过去已可用。只有日期而无时分的发布记录，保守视为该来源时区当日结束后可用。机器时间用带时区时间戳，页面采用 America/Toronto。

保存原始下载和哈希；同一文件重复导入不增加重复观测；修订新增版本而不覆盖历史。展示最新值时也能追溯到原始文件和公式。

观测的逻辑身份是系列＋期间。同值重复抓取只追加采集证据，首次见到时间保留最早实际时间；抓取时间刷新或新增发布日期证据不能单独生成“数值已修订”。数值或官方修订版本改变时保存观测版本；元数据、可用时间证据和质量处理的修正分别留审计记录，不覆盖旧证据。定义改变时另建系列并记录关系。并存来源不得自动互相覆盖，主来源变更要记录可比性。

缺失、尚未发布、过期、修订、导入失败分别标示。季度／年度值可显示最近一期及年龄，但不能计作新的月度信号。不静默填零或插值。

数据可行性阶段为每个主系列记录正常发布节奏、预计下次发布日期或“未知”、允许延迟和最大可接受年龄。过期按该系列的发布规则判断，不用统一的 30 天判断所有来源。质量异常先隔离并保留原文件，不将可疑值发布成正常数据。

人工录入记录来源、录入时间、原值与修正理由；PDF 表格需核对总数和行列对齐。

## 7. 候选信号框架：尚未验证

先展示各维度，不启用综合概率或未经校准的 0–100 分。

| 维度 | 候选判断 | 必要约束 |
| --- | --- | --- |
| 需求 | 季调成交最近 3 月均值相对前 3 月均值改善 | 变化门槛待根据历史噪声校准 |
| 库存 | 可比库存压力下降，区分成交与有效挂牌对比率的算术影响 | 需已登记并验证的季节可比方案；可用季调或另行验证的同比／历史同月比较，替代口径不能冒充季调或直接拼接；不足时只描述 |
| 融资 | 同口径新增放款利率相对 3 月前下降 | 保留组合变化的解释限制；债券与 BoC 辅助解释，不重复加分 |
| 就业 | 失业率稳定／下降，就业指标不明显转弱 | 固定平滑规则；不把降息解释为经济必然改善 |
| 广度 | 多个地区／房型同时改善 | 可用细分覆盖不足时不宣称普遍改善 |

成交、MOI、SNLR 高度相关，归入同一供需证据组，不能当独立投票重复加权。新挂牌下降本身不是正向信号；没有撤牌证据时不得断言库存下降全由成交消化。

记录每次月度评估的方向、持续次数、当前水平及反向证据。重叠三月窗口意味着连续信号也不是独立统计证据。

候选标签：改善迹象、改善持续、信号分歧、转弱、数据不足。标签的完整组合逻辑、阈值、中性区间和缺失数据策略必须在启用前版本化；目前仅为产品词汇草案。

HPI 主要用于价格确认与未来验证，不把同一期间价格变化既当预测输入又当未来成功结果。

### 月度时点与缺失处理

- 信号阶段初版评估锚点为每个自然月末（America/Toronto）。只能使用该时点已发布的最新完整期间；不同来源可以有正常发布滞后，但必须分别显示输入期间和年龄。月内更新属于预览，不新增月度记录。
- 同一评估月份重复运行、补数或修订只生成快照版本，不能增加“连续改善”次数。修订后的历史重算与当时实际发出的判断分开展示。
- 单维度连续次数只在数据所属月推进且观测合格时评估，数值可以与上月相同；重复抓取或修订同一所属月不算新月份。综合评估需需求、库存、融资、就业四个维度都有合格的新月度输入；广度作为附加证据，不参与核心连续计数。
- 按登记节奏尚未到发布时间且旧值仍合格时，标“待发布／本期尚无完整新评估”；不新增计数，保留最近完成判断及其截止月。逾期、真实缺口或不合格数据标“数据不足”。没有完成评估的月份不能计入连续改善；下一次完整评估不得跨该月份接续计数。不把未知当中性或按剩余指标重分权重。
- 正常发布滞后不自动视为过期；是否合格依据该系列的预先登记规则。扩展背景指标缺失不阻塞核心维度。
- 月末判断时点与指标所属月分开保存。回测的未来 3／6 月目标必须从实际判断时点之后开始定义，不能把已经发生但尚未发布的月份当成预测成果。

## 8. 历史验证

- 可行性阶段先尝试 24–36 个月；正式验证尽量覆盖多个周期。只有短期历史时不能宣称验证领先能力。
- 分别定义未来 3、6 个月成交变化与 HPI 变化的目标、窗口、季调和价格口径，不把二者合成模糊的“复苏”。
- 保留最后一段历史作时间顺序的样本外验证；不能用全历史调参后在同一历史报告效果。
- 训练样本的未来结果必须在训练截止时已完整发生并可获得；若 3／6 月结果窗口跨入验证区间，则剔除该训练样本。不能仅按输入月份划分训练和验证。
- 特征只使用判断日已公开的值。滚动统计、季调估计、标准化和阈值训练同样不得使用未来数据。
- 缺历史发布版本时，明确标注“使用修订后数据的近似回测”，不宣称实时可实现。
- 与仅使用成交趋势等简单基线比较；报告信号次数、误报、漏报、提前量及不同周期的稳定性。
- 先明确如何将连续信号合并为一次事件，避免将重叠窗口当大量独立成功样本。
- 人口、新盘和政策事件作为背景，未经验证不任意赋权。

## 9. Dashboard 合约

功能按阶段启用，页面不能反过来扩大当前阶段的实现范围：

| 阶段 | 首页与交互要求 |
| --- | --- |
| MVP | 总市场数据卡片、历史趋势、同比／可用季调变化、时间区间筛选、定义／来源、新鲜度和缺失提示；不展示复苏结论 |
| 扩展 | 已验证的地区／房型筛选与比较，人口、新房、建设和租赁背景；未覆盖项目清楚标示 |
| 信号验证 | 单独的实验视图展示候选判断、四组证据、广度、连续次数与反向证据；始终标注未验证状态 |
| 验证评审后 | 只有结果足以支持的规则才进入常规判断区，仍展示适用范围和误报记录；没有通过验证的规则保持实验状态或撤下 |

每个数值显示单位、地区、所属期间；详细面板提供来源、定义、季调状态、发布日期和公式。页面整体更新时间不能代替各项数据的实际新鲜度。

MVP 提供手动保存／打开月度观察记录：包含保存时点、来源截止、输入版本与期间、核心数值及变化、缺失项和来源。保存为本地文件即可，不要求新增数据库表或自动报告服务。原记录不覆盖，修订另存；这些记录不含未经验证的复苏判断，与信号阶段的月末判断快照区分。

仅提供当前阶段已有数据支持的筛选；不可比较组合禁用或清楚说明。区分原始曲线和季调曲线。数量、利率和指数分别绘图；需要归一化比较时明确基期和转换方法。

原型若使用假数据，页面持续显示“示例数据”，不得配上真实市场判断。

AI 可辅助解释已计算结果；核心数值、信号和原因由可重复程序产生。不能让 AI 编造缺失数据或自行改变计算规则。

## 10. 技术和运行

- 图表与地图联动遵循[实施计划第10节](IMPLEMENTATION_ROADMAP.md#10-图表联动合约)：同一分析区统一筛选、期间和导出，地图与列表双向同步；跨图悬停和拖选为可选增强。不同频率、来源及地理范围不隐式联动，语言切换不改变数据选择。
- 地图仅展示经核验的地区数据与边界；边界未核实时可用注明范围的城市位置点，组合区不可拆分，缺失使用独立标识。地图服务、运行主机、通知渠道及house数据来源仍待确定。
- 自动更新目标为独立任务的检查、原件保存、校验、事务入库和状态展示；区分数据所属期、最近检查时间及最近成功入库时间。调度方案尚未实施，建议检查频率不等于官方发布承诺。
- 已接受的第一版路线：Python + SQLite + Streamlit，本地网页；版本与依赖锁定在实施时完成。
- 数据采集、计算与展示分离，使后续更换 Tableau 等展示工具不必重新收集数据。
- 实际安装、Git、数据库和运行状态只在 HANDOFF 中维护，不能凭技术选型认定环境已经存在。
- 首次通过手动运行验证，再按来源发布节奏安排更新。定时器应运行在明确的主机上；本地电脑休眠时不能保证更新。
- 更新失败保留最后一次成功数据并标示陈旧状态；数据库更新采用事务，避免部分失败破坏可用快照。
- 每次更新按来源保存新增、修订、未变化、失败／隔离摘要及最近成功时间；页面显示“哪些资料更新了、哪些还没有”。异常解除记录核对依据，重跑不能自动抹掉未解决的质量问题。
- MVP 交付 `docs/USER_GUIDE.md`：打开页面、执行更新、人工文件放置、判断更新是否成功、查看旧数据和复制错误摘要的步骤。技术日志放详情，首页用中文说明状态与可执行动作。
- 恢复资料需覆盖原始文件及 manifest、系列／导入／公式配置、人工修正与质量处理、版本可用时间证据及月度记录；可通过完整数据库备份加外部文件保存，或可重放的配置／处理记录实现。首次验证一次恢复，结构迁移前备份，方式与命令写入使用指南；仅重新导入原始数值不等于恢复完整历史。
- 第一版不依赖付费资料。不购买订阅、不发布网站、不推送远程或配置外部通知，除非后续任务授权相应操作。
- 不把公开可读视为可无限再分发；若将订阅数据或报告内容放入公开网站，先核实具体使用条款。

## 11. 阶段验收

### 数据可行性完成

- 核心来源列出已验证的系列、单位、范围、季调／平滑、历史起止与获取方式。
- 将来源标为“可用”需要实际样本能追溯到原始文件；拿不到的字段和替代方案明确列出，不能仅靠计划判定可用。
- 明确 TRREB 自动获取或人工导入的可行路径，不将找到链接视为接入成功。
- 交付 `docs/DATA_DICTIONARY.md`、`docs/SOURCE_COVERAGE.md` 和带来源清单的原始样本；前者记录每个实际系列的定义，后者记录访问方式、历史范围、缺口、发布节奏和验证证据。
- 每个必需指标组至少有可核对的真实样本，或有已记录的不可用结论；形成“核心齐备，可进入完整 MVP”或“部分可用，继续已支持模块”的结论。不可用结论可结束可行性调查，但不视为对应数据已接入。

### MVP 完成

- 实际数据可重复导入；数据库无重复观测；至少核对正常样本、修订与缺失情形。
- MOI、SNLR、同比、利率变化的单位和分母有针对性检查，覆盖零分母与跨口径拒绝。
- 月末库存不会被误加总，未结束月份不会混入完整月份比较。
- 页面实际运行并检查主要筛选、来源展开、旧数据提示和异常路径。
- 暂未达到历史长度要求的图表明确显示可用范围，不补造数据。
- 第 2 节必需指标组都可展示；提供启动、导入和更新命令，按第 10 节恢复一次含修订／缺失或人工处理的样本，核对关键值、版本引用和处理状态一致。边界情形可用隔离的测试样本验证，不混入真实市场数据。手动 CSV 导入可满足 MVP，自动更新不是该阶段的完成门槛。
- 完成一次月度观察记录的保存、重新打开与数值核对，使用指南与实际操作一致；更新摘要能区分单来源成功和全部来源成功。

### 扩展模块完成

- 人口、建设、condo 新房、租赁、地区／房型比较及购买力情景分别验收，不要求一起上线。
- 每个数据模块有定义、来源范围、实际样本核对、原始频率、页面解释与缺失处理；政策记录有原始公告与生效状态，情景工具有固定假设与可复现计算。
- 按模块记录“完成／部分可用／无合适数据”；扩展失败不破坏核心页面。只在有足够字段覆盖的地区或房型提供比较。

### 信号功能完成

- 所有启用规则有公式、版本、输入、门槛、缺失处理和可读解释。
- 历史验证方法和实际结果都有可复现记录；未完成验证时只展示实验标签。
- 验证失败也是有效研究结果；不能为了宣布完成调参到“看起来有效”。进入常规判断区前记录与基线的比较、样本限制和采用／保留实验／弃用决定。
- 更新交接文件，区分实现、测试、未验证、受阻和未开始事项。
